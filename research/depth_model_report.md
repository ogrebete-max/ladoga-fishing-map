## 2. Оцифровка отметок (OCR)

1. **Чернила.** Сила штриха S = локальный фон (серое замыкание max(R,G,B), окно 7×7) − max(R,G,B), только малонасыщенные
   (чёрные/серые) пиксели; гистерезисный порог 0,45/0,65 от медианного контраста штриха карты. Цветные элементы — голубая заливка 0–5 м,
   жёлтая суша, пурпурные фарватеры, рамки врезок, розы компасов — отсекаются по насыщенности.
2. **Линии.** Морфологическое открытие 32 направленными отрезками длиной 17 пикс. (цифра высотой ~10 пикс. такого отрезка не вмещает)
   убирает изобаты, берег, сетку, кабели; пунктиры — по цепочкам коллинеарных вытянутых фрагментов. Вручную исключены черные розы компасов
   (28081, 28070), углы рамки и врезка 1:10 000 «Проход южнее о. Торпаков» на 28079.
3. **Символы.** Связные компоненты → патчи 24×24 → CNN-классификатор (0–9, «(», «)», прочее, слипшиеся символы). Обучающую разметку
   я сделал сам по листам с контекстом: 360 + 480 кластеров (кластеризация 79 и 86 тыс. патчей по PCA и по признакам сети) — около 82 тыс.
   размеченных символов, плюс 298 отдельно проверенных мелких индексов. Точность на отложенных символах 99,5 %. Слипшиеся цифры
   разрезаются наклонными разрезами (курсив), вариант выбирает сеть.
4. **Отметки.** Соседние по горизонтали символы собираются в число: целая часть — 1–2 крупные цифры, десятые — цифра-индекс (меньше и ниже;
   опора — самая высокая цифра целой части). Скобки и пунктирный кружок вокруг числа (наименьшая глубина над опасностью) отбрасываются,
   отметка получает `danger_least_depth`. Надписи, высоты, номера, числа неправильной структуры не принимаются.
5. **Положение отметки** — центр целой части числа (правило отечественных морских карт) → WGS84 по привязке листа. Горизонтальная
   погрешность: привязка 1–7 м плюс ±1 пикс. центра числа (2–9 м), т. е. ~5–15 м на листах 1:50 000 и ~3–5 м на 1:10 000.

## 3. Контроль качества

**Precision (проверка глазом).** Случайная выборка 180 отметок из итогового набора (seed 777, пропорционально числу отметок листов);
для каждой — увеличенный фрагмент скана с рамкой и прочитанным значением. Верно 178. Ошибки: 3₆ прочитано как 6 (тройку пересекает
зелёный пунктир, 28081) и 8₆ → 8 (индекс касается пурпурной линии, 25069). Сомнительны 3 индекса (5 или 6) на зернистых сканах 28070 и 28071.
Предыдущая выборка из 180 (до последних доработок) дала тот же результат, 178/180.

**Recall.** 16 случайных окон 220×160 пикс. в воде, по 2 на лист (вне врезок и рамок более крупных карт): на скане 111 отметок,
найдено 105. Пропущены: 2 в пунктирных кружках опасностей, 2 на линиях изобат, 1 у знака камня, 1 на краю окна у изобаты.
Две из найденных без десятых (8₂ → 8, 2₂ → 2).

**Автоматическая отбраковка.** Флаги в поле `qc`; отбракованные отметки остаются в файле с `used_in_model=false`.

## 4. Сетка глубин

- **Данные.** 18 411 отметок (вес 1); вершины изобат 2/5/10/15/20/30/50 м трёх листов 1:50 000 через каждые 40 м (34 577 точек, вес 0,35;
  внутри рамок 1:10 000 не используются); береговая линия OSM как 0 м (8 388 точек, вес 0,5).
- **Акватория.** Полигон Ладожского озера OSM (заливка от точки в открытом озере; барьеры — все линии мультиполигона с островами) и речные
  полигоны OSM (Волхов, Сясь, Свирь, Нева, протоки, Загубская губа) — только в радиусе 1,2 км от отметок, стоящих в реке; каналы исключены.
  Всё это пересекается с рамками 8 карт. Суша и места без карт — «нет данных».
- **Метод.** Минимальная кривизна с натяжением на графе ячеек воды: лапласиан с условием Неймана на берегу, поэтому глубина не «перетекает»
  через косы, острова и дамбы. Разреженная система решается алгебраическим мультигридом (pyamg). Затем значения ограничиваются диапазоном
  данных в радиусе 1,5 км ±0,5 м, чтобы сплайн не давал выбросов между редкими глубокими отметками. Ячейка 50 м (0,00045° × 0,0009°);
  на картах 28081 и 28070 — 25 м.
- **Подбор параметров** (кросс-валидация на районе 25069, 5 групп). Вес кривизны 0,1 / 0,5 / 2 и натяжение 0,02 / 0,2 дают почти одинаковую
  ошибку: медиана 0,31 м, 90 % ≤ 1,10 м. Без изобат хуже: 0,33 / 1,17 м, поэтому изобаты оставлены. Итог: кривизна 0,5, натяжение 0,1,
  вес изобат 0,35.

Одним файлом сетка 50 м на весь район весит ~14 МБ (base64), поэтому она **разбита по листам**, а `depth_grid.json` служит индексом.
Формат каждого файла: `{id, bounds: [[S,W],[N,E]], dlat, dlon, cell_m, nx, ny, scale: 10, nodata: 65535, data: base64(Uint16 little-endian,
глубина × 10)}`; строка 0 — северная, центр ячейки (r, c) = [N − (r + 0,5)·dlat, W + (c + 0,5)·dlon]. Листы перекрываются, искать по
`priority` (сначала 1:10 000). Декодер ниже проверен на Node.js: расхождение с моделью в среднем 0,016 м.

```js
// глубина в точке по data/depth_grid.json (null вне модели)
const depthIdx = await fetch('data/depth_grid.json').then((r) => r.json());
const depthCache = new Map();
function loadDepthFile(f) {
  if (!depthCache.has(f.file)) depthCache.set(f.file, fetch(f.file).then((r) => r.json()).then((g) => {
    const bin = atob(g.data), u = new Uint16Array(bin.length >> 1);
    for (let i = 0; i < u.length; i++) u[i] = bin.charCodeAt(2 * i) | (bin.charCodeAt(2 * i + 1) << 8);
    g.u = u; delete g.data; return g;
  }));
  return depthCache.get(f.file);
}
async function gridDepthAt(lat, lon) {
  for (const f of depthIdx.files) {
    const [[S, W], [N, E]] = f.bounds;
    if (lat < S || lat > N || lon < W || lon > E) continue;
    const g = await loadDepthFile(f);
    const fx = (lon - W) / g.dlon - 0.5, fy = (N - lat) / g.dlat - 0.5;
    const x0 = Math.floor(fx), y0 = Math.floor(fy), tx = fx - x0, ty = fy - y0;
    let s = 0, w = 0;
    for (const [dy, dx, k] of [[0, 0, (1 - tx) * (1 - ty)], [0, 1, tx * (1 - ty)], [1, 0, (1 - tx) * ty], [1, 1, tx * ty]]) {
      const y = y0 + dy, x = x0 + dx;
      if (y < 0 || x < 0 || y >= g.ny || x >= g.nx) continue;
      const v = g.u[y * g.nx + x];
      if (v !== g.nodata) { s += k * v / g.scale; w += k; }
    }
    if (w > 0.05) return s / w;           // м от среднего многолетнего уровня; для 2026 г. вычесть ~0,9 м
  }
  return null;
}
```

## 6. Слабые места

- **Свирская губа, глубокая часть (лист 25070).** Жёлоб 50–78 м (≈60,63–60,74° с. ш., 32,38–32,44° в. д.) и восточный берег к северу
  от губы (60,75–60,85°): отметки стоят примерно через 1 км, склоны крутые. Медиана ошибки 0,5 м, 90 % ≤ 1,9 м, отдельные точки — до 10 м.
- **Каменистые банки и гряды.** Район Стороженского маяка и рифа (60,45–60,65°, 32,5–32,6°), банки у Кареджи и Сухо: медиана ошибки
  0,6–0,9 м. Сетка сглаживает отдельные камни между отметками. Около 600 отметок «над опасностью» (в скобках или пунктирном кружке)
  сохранены, но как точки 50 м они видны лишь как небольшие пятна; для рыбалки на бровках смотреть сами отметки и растр карты.
- **Узкие фарватеры и каналы** (прорезь в истоке Невы на 28070, фарватер Волхова). Канал шириной 60–100 м на сетке 25 м получается
  сглаженным и мельче, чем на карте.
- **Мелководье у берега (0–2 м).** Берег взят из OSM, т. е. современный, а не с карты. Тростники, осушки и переформирование берегов
  с 1930–70-х гг. дают относительную ошибку около 30 %.
- **Реки.** Устье Волхова до 60°05′ (28081) и Нева у Шлиссельбурга (28070) промерены подробно. Свирь, Сясь и протоки описаны только там,
  где на картах есть отметки (в радиусе 1,2 км); выше по рекам сетки нет.
- **Не покрыто.** Открытое озеро севернее 60°25′ между 31°19′ и 32°05′ в. д. и всё вне рамок 8 карт — в сетке «нет данных».
- **OCR.** Около 5 % отметок не найдено (на изобатах, в пунктирных кружках); этот пробел частично закрывают изобаты. Примерно 1 % прочитан
  с ошибкой, в основном без десятых или с неверными десятыми; грубые ошибки (обрезанная первая цифра) — доли процента.
- **Возраст промера.** 1930–1970-е гг., местами карты шельфа 1990-х. Дноуглубление, заносимость устьев и изменения фарватеров
  с тех пор не учтены.

## 7. Датум глубин

Все глубины — отметки, сетка, изолинии, заливка — отсчитаны **от среднего многолетнего уровня Ладожского озера (+5,1 м БС, посты Сухо и
Сторожно)**, как на картах ГУНиО. В 2026 г. уровень примерно на **0,9 м ниже** нормы, поэтому реальные глубины сейчас меньше на ~0,9 м:
изолиния «2 м» — это ~1,1 м воды. В приложении: `глубина сейчас ≈ глубина модели − 0,9` (поле `level_2026_correction_m` в индексе).

## 8. Воспроизведение

Порядок запуска в `research/raw/depth_model/`: `extract_cc.py` (чернила, линии, компоненты) → `patches.py` → разметка (`cluster.py`,
`cluster2.py`, `labels_round2.py`, `subx.py`, `subx_cluster.py`) → `train_char2.py` (CNN, `charnet.pt`) → `words.py` (чтение отметок) →
`fetch_osm.py`, `build_mask.py` (вода OSM) → `merge_soundings.py` → `qc.py` → `build_grid.py cv 5` → `cv_screen.py` → `write_soundings.py` →
`tune.py` → `build_grid.py solve` → `build_grid.py cv 5` → `make_isolines.py` → `make_tiles.py 9 15` → `export_grid.py` → `stats.py`.
Листы проверки (выборки precision и recall, наложение изолиний модели на сканы) строят `review.py`, `viz_check.py`, `sheet_idx.py`.
