## 1. Схема

- У всех 509 записей есть 17 полей из BRIEF. Типы верные: lat/lon — float, `coord_precision_m` — int > 0, `fish` — список строк с заглавной буквы, `date` — `YYYY-MM-DD` (у hazard — `YYYY`), `season` ∈ {ice, open_water, ""}, `kind` и `confidence_class` из допустимых значений.
- Дополнительные поля: `area` (509), `place_label`, `place_anchor`, `date_basis`, `post_date`, `route_note` (по 495), `catalog_place` (352), `polygon` (3). **Для `build_data.py` они безвредны.** `research_reports()` читает только свои ключи, а `timeseries()` — только `dated_reports_*`, которых в файле нет. Это подтвердила сборка на копии. Два следствия:
  - `polygon` игнорируется: районы мереж видны только точкой-центроидом. Поэтому в `coord_precision_m` записан радиус полигона (1,2–3,3 км) вместо 10 м.
  - 470 датированных отчётов **не попадут** в сезонную статистику `timeseries`. Это ожидаемо. Включать их туда без ручной проверки видов рыб не советую.
- В `date_basis` новое значение `text:weekday` — дата взята по дню недели из текста.
- В корне файла добавлен блок `review` со ссылкой на этот отчёт; сборка его не читает.
