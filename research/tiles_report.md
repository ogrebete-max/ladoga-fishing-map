## 3. Метод

### 3.1 Привязка
* Навигационные карты — готовые модели агента `charts2` (`research/raw/charts2/georef/*.json`: полином 2–3 степени «долгота, изометрическая широта Красовского → пиксель скана» по узлам картографической сетки). Переход WGS84 → СК-42: напечатанный на карте сдвиг долготы (7,5–8,3″ к востоку), для листов без надписи (28081, 28070) — pyproj EPSG:4326→4284.
* Новое: **28070 изд. 1989** — внутренняя сетка напечатана только крестиками, поэтому: 4 угла рамки (трассировка линий рамки, rms 0,4–1 пикс.) + 11 найденных крестов сетки через 1–2′ → полином 2-й степени, невязка 1,2 м, LOO 2,7 м (0,85 м/пикс.). `research/raw/tiles_src/georef_new.py`, `georef/20g.json`.
* Новое: **врезка «Проход южнее острова Торпаков» 1:10 000** на листе 28079 (раньше она висела поверх суши южнее Сторожно как часть карты 1:25 000). Привязана по своим рискам (меридианы 32°37′/38′/39′, параллель 60°33′, шкала 1″) и вырезана из листа 28079; совпадение с основной картой (о. Торпаков, Стороженский риф, камни) — в пределах ~5 м. `georef/14A.json`.
* **Генштаб**: все 4 листа перепривязаны заново по перекрестьям 2-км сетки (как `depth/genshtab/georef_grid.py`), но модель — гомография + кубическая поправка на деформацию бумаги/скана, короткие «плечи» измерения; точность (10-кратная кросс-проверка): P-36-135,136 — 8,9 м (было 16,4 м), P-36-137,138 — 15,4 м (было 23,5), P-36-126 — 7,0 м (8,4), O-36-3 — 8,8 м (11,4). `tiles_src/georef_genshtab_hr.py`.

### 3.2 Рендер тайла — одна передискретизация прямо из пикселей скана
Для каждого пикселя тайла (256 px + поле 8 px): Web Mercator → WGS84 → СК-42 → модель привязки → координата в исходном скане (точное отображение считается в узлах через 8 px и интерполируется билинейно — ошибка ≪ 0,01 px). Дальше ровно одна передискретизация:
* если скан детальнее тайла (z ≥ 13–14 для 1:50 000) — **кубический сплайн** (scipy, с префильтром);
* если тайл грубее скана (обзорные зумы) — **суперсэмплинг** с шагом ≤ 1 пикс. скана и **сведение ядром Lanczos-3** (т. е. Lanczos, растянутый на размер пикселя тайла — без алиасинга).
Никаких промежуточных растров, перепроецированных картинок и повторных JPEG/WebP — старые оверлеи проходили: медианный фильтр → бикубика → WebP q62–65 → растяжение браузером.

**Наложение.** Всё за внутренней рамкой (поля, шкалы, легенды) прозрачно; заголовки, примечания, «схемы использованных материалов», эмблемы и таблица корректуры внутри рамок (все они на суше) закрашены цветом суши того же листа (прямоугольники в пикселях скана, `cutouts` в скрипте; цвет — медиана кольца вокруг прямоугольника), так что на карте нет ни надписей, ни «заплаток» из других листов. Внутри одного масштаба (например, 25069/25068, 25069/25070, 25067/25068) каждый пиксель берётся с того листа, в глубине которого он лежит, поэтому шов идёт по середине перекрытия, а рамки/заголовки соседа не видны. Между масштабами — «самый подробный сверху», но **только когда его цифры читаются на этом зуме** (высота цифры 2 мм на бумаге ≥ 8 px на экране): 1:125 000/1:100 000 — с z12, 1:50 000 — с z13, 1:25 000 — с z14, 1:10 000 — с z15. Более подробные листы на меньших зумах уходят вниз (заполняют только дыры): иначе на z14 в устье Волхова вместо читаемых цифр 1:50 000 (≈20 px) показывался бы 1:10 000 с цифрами в 4 px — так было со старыми оверлеями.

### 3.3 Подготовка исходников и резкость
* Главная причина «мыла» в старых оверлеях — медиана 3×3 по исходнику (`warp_chart.py --denoise 1`): она съедает тонкие штрихи и индексы цифр (сравнение: `research/raw/tiles_check/denoise/_cmp_16.png`, правый нижний — медиана). Вместо неё — мягкое **non-local means** (OpenCV, h = 5): убирает JPEG-шум и фактуру бумаги на ровных местах, штрихи цифр не трогает; тайлы от этого ещё и на 15–20 % меньше.
* GIF 28070 (6 «плоских» цветов) перекрашен в оттенки соседних листов 28071/25067, чтобы лист не выделялся.
* После сборки тайла — мягкая нерезкая маска (σ 0,9 px, 60 %, порог 2 уровня), нормированная по альфе (без ореолов у края рамки).

### 3.4 Формат
Тест на одних и тех же тайлах z9–z16 (сумма по 8 тайлам, WebP q85 = 1,0): WebP q90 — 1,21; **PNG-8 64 цв. — 1,70; PNG-8 128 цв. — 2,08** (imagequant без дизеринга + oxipng); WebP lossless с палитрой 64/128 — 1,56/1,91. На увеличенных зумах разрыв больше (z15: 2,8 КБ WebP против 13 КБ PNG-8). Разборчивость q85 и PNG-8 одинаковая (`tiles_check/fmt3/_fmt_cmp.png`, ×3) — сканы с плавными переходами тона палитре невыгодны. Итог: **везде WebP q85** (method 6, альфа без потерь), один шаблон URL.

### 3.5 Какие тайлы есть
Только пересекающие покрытие карт **и** рамку района (с. ш. 59,85–60,80, в. д. 30,90–33,40); полностью прозрачные не пишутся.
* `charts`: z9–15 по всему покрытию; **z16 — только в прямоугольниках листов 1:10 000/1:25 000** (28081; 28079 + врезка; 28070 + 28071), список прямоугольников — `index.json → layers[0].detail.regions`.
* `genshtab`: z9–14 по 4 листам.

## 6. Подключение в Leaflet

`site/tiles/index.json` → `layers[]` (`charts`, `genshtab`): `url`, `minZoom`, `maxZoom`, `maxNativeZoom`, `bounds` ([[ю, з], [с, в]]), `attribution`, `tiles_count_by_zoom`, `bytes_by_zoom`, `list` (плоский список для офлайн-загрузчика — именно это поле уже читает `PACKS.charts` в `app.js`), у `charts` ещё `detail.regions` (где есть z16) и `sources` (листы, годы, рамки).

```js
// вместо L.imageOverlay(nav*.webp / genshtab_*.webp)
const TILE_IDX = await fetch('tiles/index.json').then((r) => r.json());
function tileLayerFromIndex(id, opts = {}) {
  const l = TILE_IDX.layers.find((x) => x.id === id);
  const base = {
    minZoom: 7, minNativeZoom: l.minZoom,          // z7–8 — уменьшенные тайлы z9
    maxZoom: 19, maxNativeZoom: l.maxNativeZoom,    // charts: 15, genshtab: 14 — дальше растягиваются
    bounds: l.bounds, attribution: l.attribution,
    errorTileUrl: 'data:image/gif;base64,R0lGODlhAQABAAAAACH5BAEKAAEALAAAAAABAAEAAAICTAEAOw==',
    ...opts,
  };
  const parts = [L.tileLayer(l.url, base)];
  for (const r of l.detail?.regions || []) {     // z16 — только листы 1:10 000 / 1:25 000
    parts.push(L.tileLayer(l.url, { ...base, minZoom: 16, minNativeZoom: 16, maxNativeZoom: 16, bounds: r.bounds }));
  }
  return L.layerGroup(parts);                      // прозрачность: group.eachLayer((t) => t.setOpacity(v))
}
const chartsLayer = tileLayerFromIndex('charts', { pane: 'charts', opacity: state.chartOpacity });
const genshtabLayer = tileLayerFromIndex('genshtab', { opacity: state.genshtabOpacity });
```

* Внутри рамок карт тайлы непрозрачны (прозрачны только за рамками), прозрачность слоя 0,8–1 — по вкусу; `pane: 'charts'` (z-index 250) в `app.js` уже есть.
* `sw.js` уже отдаёт `/tiles/` из кэша (cache-first) — менять нечего, кроме `VERSION` при выкладке.
* Офлайн-пакет «Навигационные карты глубин» (`PACKS` в `app.js`) сам прочитает `tiles/index.json` и оба списка (`charts_tiles.txt`, `genshtab_tiles.txt`): ≈ 128,9 МБ, 59527 файлов. Если Генштаб нужен отдельным пакетом — фильтровать `idx.layers` по `id`.
* Старые `site/overlays/nav*.webp` и `genshtab_*.webp` (≈ 16 МБ) после переключения можно убрать из сайта.

Нужны `research/raw/charts2` (сканы + georef), `research/raw/tiles_src` (новые сканы, их привязка), `research/raw/depth/genshtab`; Python 3.12 + numpy, scipy, Pillow, pyproj, opencv-python-headless (NLM), по желанию imagequant/pyoxipng (только для теста PNG-8). BLAS принудительно однопоточный — параллельность даёт пул процессов. Кэши `research/raw/tiles_src/cache/*.npy` (≈ 1,7 ГБ, планарные RGB после NLM) можно удалить — `prepare` их пересоздаст.

## 8. Ограничения

* Исходники 1:50 000 — 150 dpi, лучше в открытом доступе нет. На z15 такие листы увеличены в 3,6 раза (мягко), а участки, где есть только 1:125 000/1:100 000 (суша, открытое озеро на севере), на z15 увеличены в 5–7 раз — они есть только потому, что z15 сделан по всему покрытию.
* Листы разных изданий (1984–2000) и разных сканов: на стыках масштабов возможны сдвиги 5–15 м (точность привязки + генерализация) и разный оттенок суши/воды; внутри одного масштаба шов проходит по середине перекрытия и почти не виден.
* Заголовки/примечания/схемы внутри рамок закрашены цветом суши того же листа (все они на суше); врезка «Проход южнее о. Торпаков» перенесена на своё место.
* Устье Волхова — изд. 1984 г. (корр. 1993); найденный скан 300 dpi изд. 1978 г. не использован (старее). На листах 28081 и 28071 в районах, обведённых фиолетовым пунктиром, глубины даны от проектного уровня (на 0,9–1 м ниже среднего), остальное — от среднего многолетнего уровня (+5,1 м БС). Не для навигации.
* Вне покрытия (полоса южнее 59,9° и восточнее 31,63°, угол у Шлиссельбурга на z16) тайлов нет — Leaflet получит 404 (`errorTileUrl` выше их гасит).
* P-36-125 (о. Сухо) и листы Генштаба 1:50 000 в открытом доступе по-прежнему не найдены.
